# Billing Module (Phase 1) Implementation Plan

This plan details the steps to build **Phase 1 of the Billing Module** featuring an A4 Invoice Form, live Preview Panel, and PDF generation architecture in Angular 22.

---

## User Review Required

> [!IMPORTANT]
> - **No Database Layer Interaction (Yet)**: All invoice state is held in memory using Angular Signals. The architecture will allow saving invoices to SQLite in future phases without major rewrites.
> - **PDF Ready Structure**: The `PdfService` will be prepared as an abstraction layer ready to wrap `html2canvas` + `jsPDF` libraries in subsequent phases.
> - **Print Media CSS**: Special media print rules will be written to hide forms and side navs, formatting the `InvoicePreview` component as a clean page when printed or converted to PDF.

## UI Styling (SCSS)
- **Grid Layout**: Side-by-side flex layout on desktop, responsive stack on mobile.
- **A4 Styling**: CSS classes defining exact 210mm x 297mm dimensions, print margins, box shadows to look like paper sheets, and `@media print` directives to fit exactly on standard paper.

## Verification Plan

### Automated Tests
- Run `npm run test` to verify existing and new spec files.
- We will add spec tests for `CalculationService`, `InvoiceService`, and `BillingPage` component.

### Manual Verification
1. Run local dev server: `npm run start`
2. Open page: `http://localhost:4200/`
3. Verify that typing customer details or adding/deleting rows immediately redraws the right-side A4 paper sheet preview.
4. Verify that entering rate=100 and qty=5 updates item amount to 500, updates subtotal, and correctly rounds grand total.
5. Click **Generate PDF / Print**. Verify it triggers browser print dialog targeting the single A4 preview page.
