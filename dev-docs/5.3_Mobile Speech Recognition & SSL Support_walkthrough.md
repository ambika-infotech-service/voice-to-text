# Walkthrough - Mobile Voice-to-Text Fixes

This walkthrough details the changes made to fix the voice-to-text microphone permission denied and state-locking errors on mobile browsers.

## Root Cause Analysis

1. **Permission Denied / Insecure Context:** Modern browsers (like Chrome on Android or Safari on iOS) require a **secure context** (HTTPS or localhost) to use the Web Speech API (`SpeechRecognition`). When accessing the app via `http://<ip-address>:4200` over local network, the browser immediately rejects the microphone access request, throwing a `not-allowed` error.
2. **"Recognition has already started" Error:** When a session fails (or when the user starts it a second time), the previous `SpeechRecognition` instance was being reused. If it was already active, or in the process of aborting/erring, calling `.start()` on the same instance would throw the browser error `Failed to execute 'start' on 'SpeechRecognition': recognition has already started`.

## Changes Made

### 1. Recreating and Cleaning Up SpeechRecognition Instances
Modified [browser-speech-provider.ts](file:///Users/smitpatel/Desktop/Personal%20Projects/voice-to-text/src/app/core/speech/providers/browser-speech-provider.ts) to clean up event listeners and discard the old instance before starting a new one.

- Added a `cleanup()` method:
  ```typescript
  private cleanup(): void {
    if (this.recognition) {
      this.recognition.onstart = null;
      this.recognition.onresult = null;
      this.recognition.onerror = null;
      this.recognition.onend = null;
      try {
        this.recognition.abort();
      } catch {
        // Ignore errors during abort
      }
      this.recognition = null;
    }
    this.isInitialized = false;
  }
  ```
- Called `this.cleanup()` inside `start()` and `abort()` methods to guarantee a fresh, untangled instance is constructed upon every session request.
- Added a `private status` property to prevent the async `onend` event from overriding the error state when `onerror` and `onend` fire consecutively.

### 2. Added HTTPS Dev Script for Mobile Support
Modified [package.json](file:///Users/smitpatel/Desktop/Personal%20Projects/voice-to-text/package.json) to support serving local builds over SSL/HTTPS.
- Added: `"start:mobile": "ng serve --host=0.0.0.0 --ssl"`

## Verification & Mobile Testing Steps

To test on your mobile device:

1. **Start the server with SSL:**
   Run the newly added command in your terminal:
   ```bash
   npm run start:mobile
   ```

2. **Locate your local IP Address:**
   Ensure your Mac and mobile phone are connected to the same Wi-Fi network. Find your local IP (e.g. `192.168.1.15`).

3. **Access the App via HTTPS on Mobile:**
   On your phone, navigate to:
   ```
   https://<your-local-ip>:4200
   ```
   > [!IMPORTANT]
   > Make sure you use `https://` (not `http://`).

4. **Accept SSL Warning:**
   Since the server uses a self-signed dev certificate, your browser will warn you that the connection is not private.
   - **On Android (Chrome):** Tap **Advanced** -> **Proceed to <your-local-ip> (unsafe)**.
   - **On iOS (Safari):** Tap **Show Details** -> **Visit this website** -> **Visit Website**.

5. **Test Voice-to-Text:**
   - Tap the microphone button.
   - The browser will ask for microphone permissions. Allow it.
   - Talk and verify that the live transcription outputs correctly.
   - Stop and click again to confirm that subsequent recording sessions start and stop without errors.
