# Mobile Speech Recognition & SSL Support

The voice-to-text functionality fails on mobile device browsers when accessed via HTTP (e.g., `http://192.168.x.x:4200`) because SpeechRecognition requires a secure context (HTTPS or localhost). This results in a persistent `not-allowed` error. Additionally, subsequent clicks throw a `recognition has already started` error because the existing `SpeechRecognition` instance is not cleaned up or recreated.

This plan addresses both issues by:
1. Re-creating the `SpeechRecognition` instance for each new session and cleaning up/detaching events on the old one.
2. Tracking the internal status state to prevent the `onend` event from overriding the error state immediately after `onerror`.
3. Adding a SSL-based script `start:mobile` in `package.json` to easily serve the app over HTTPS.

## Proposed Changes

### Core Speech Module

#### [MODIFY] [browser-speech-provider.ts](file:///Users/smitpatel/Desktop/Personal%20Projects/voice-to-text/src/app/core/speech/providers/browser-speech-provider.ts)
- Track status internally via `private status: 'idle' | 'listening' | 'processing' | 'error' = 'idle'`.
- Implement a `cleanup()` method to detach event listeners and abort the active `SpeechRecognition` instance.
- Call `cleanup()` inside `start()` and `abort()` to ensure a clean slate and recreate `SpeechRecognition` on every new start.
- Update `onend` to check `if (this.status !== 'error')` before emitting `{ status: 'idle' }` to ensure the error message is not immediately cleared/overwritten when the browser ends the session.

---

### Configuration

#### [MODIFY] [package.json](file:///Users/smitpatel/Desktop/Personal%20Projects/voice-to-text/package.json)
- Add a new script: `"start:mobile": "ng serve --host=0.0.0.0 --ssl"` to run a local dev server with HTTPS/SSL, which is required for speech recognition to function on other devices on the same network.

## Verification Plan

### Automated Tests
- Run unit tests to make sure there are no regressions:
  `npm run test` or `npx vitest`

### Manual Verification
- Start the server using the new command:
  `npm run start:mobile`
- Connect a mobile phone to the same Wi-Fi network and open `https://<your-ip>:4200`.
- Accept the self-signed SSL certificate warning ("Advanced" -> "Proceed anyway").
- Click on the microphone, grant microphone permissions, and verify that speech recognition works.
- Verify that error states are correctly displayed and retrying works smoothly.
