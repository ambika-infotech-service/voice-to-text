# Implementation Plan - Intelligent Product Search Engine

We will build an intelligent, extensible, and high-performance Product Search Engine in our Angular 22 + Capacitor SQLite application. This search engine converts recognized speech (or text query) into matching products from the local SQLite database.

## User Review Required

No breaking changes or risky migrations are required. The search engine will operate as a standalone core service `ProductSearchService` utilizing the existing database schemas (`Product`, `Category`, `Attribute`, `AttributeValue`, `Alias`).

## Proposed Changes

We will create a set of clean, reusable, and modular TypeScript files in `src/app/core/search`.

---

### Component: Product Search Engine (`src/app/core/search`)

We will add a new search module under `src/app/core/search` with the following files:

#### [NEW] [search.model.ts](file:///Users/smitpatel/Desktop/Personal Projects/voice-to-text/src/app/core/search/models/search.model.ts)
Contains all TypeScript interfaces, including:
- `SearchResult` returned by the search engine.
- `SearchableProduct` representing the indexed structure of products cached in memory.
- `NormalizationRule` interface for extensible preprocessing rules.
- `ScoringProcessor` and `ScoringContext` interfaces for modular scoring strategies.

#### [NEW] [normalization.ts](file:///Users/smitpatel/Desktop/Personal Projects/voice-to-text/src/app/core/search/utils/normalization.ts)
Implements an extensible normalization pipeline including:
- `LowercaseRule`: Converts string to lowercase.
- `PunctuationRule`: Replaces common punctuation marks with spaces.
- `UnitSynonymsRule`: Normalizes variations for sizes/weights/counts (e.g., `twenty`, `20 litre`, `20 ltr`, `20l` -> `20l`; `litre`, `liter`, `ltr` -> `l`; `kilogram`, `kgs` -> `kg`; `pieces`, `piece` -> `pcs`).
- `WhitespaceRule`: Trims and collapses multiple spaces.
- A helper class `Normalizer` to chain rules and process strings.

#### [NEW] [levenshtein.ts](file:///Users/smitpatel/Desktop/Personal Projects/voice-to-text/src/app/core/search/utils/levenshtein.ts)
Implements the Levenshtein Distance algorithm in TypeScript:
- Calculates edit distance between two strings.
- Computes similarity score `1 - distance / Math.max(len1, len2)`.
- Handles fuzzy matching thresholds.

#### [NEW] [product-search.service.ts](file:///Users/smitpatel/Desktop/Personal Projects/voice-to-text/src/app/core/search/services/product-search.service.ts)
Implements the core `ProductSearchService` matching the 11 requirements:
- **In-Memory Cache**: Loads products once from the database using a comprehensive SQL query resolving Category, Brand, and Aliases. Caches them to ensure fast sub-millisecond execution.
- **Multistage Processing**: Normalization, tokenization, exact alias matching, exact name matching, keyword scoring, fallback LIKE/partial matching, fuzzy Levenshtein matching, ranking, and formatting results.
- **Extensible Ranking**: Employs a modular scoring registry where `ScoringProcessor`s are registered, ensuring developers can add synonym lookups, recent purchase history, AI ranking, or multilingual support in the future without modifying the search engine orchestration.
- **Rules Enforcement**: Truncates results based on confidence thresholds:
  - Confidence > 90%: returns `bestMatch` and products list with that best match.
  - Confidence 60-90%: returns top 5 suggestions.
  - Confidence < 60%: returns empty result.

#### [NEW] [product-search.spec.ts](file:///Users/smitpatel/Desktop/Personal Projects/voice-to-text/src/app/core/search/services/product-search.spec.ts)
Unit tests for `ProductSearchService` validating:
- Normalization rules.

- Levenshtein distance correctness.
- Alias match shortcut.
- Name match shortcut.
- Keyword scoring logic.
- Confidence classification rules.
- Extensible scoring injection.
