# Customer Management Module Implementation Plan

Implement a complete Customer Management Module for the Angular 22 ERP application. This includes SQLite schema updates, transactional repositories, business services, standalone page components, validation patterns, and reusable toast/confirmation dialog utilities.

## User Review Required

> [!IMPORTANT]
> **Database Version Bump:** We will create a new migration (`MigrationV2`) and bump the `DB_VERSION` constant in `database.constants.ts` to `2`. This will run the table creations for `customers` and `customer_workers` automatically on application startup.
>
> **Global Router Configuration:** To accommodate paths like `/customers`, `/customers/new`, `/customers/:id`, and `/customers/:id/edit`, we are upgrading the application shell navigation in `app.html` and `app.ts` from local signal-based tab switching to standard Angular routing (`RouterOutlet`, `RouterLink`, `RouterLinkActive`). The existing views (Billing, Speech Demo, Database Demo) will also be mapped as lazy-loaded or direct routes.

## Open Questions

None at this time. All requirements are clear and align directly with the provided system design rules.

## Verification Plan

### Automated Tests
Run vitest suite to verify components and services build and pass:
```bash
npm run test
```
(Specifically we will also add a unit test for the `CustomerRepository` to verify transactional integrity and search logic).

### Manual Verification
1. Boot application, verify SQLite bootstrapping, schema v2 creation, and navigation rendering.
2. Navigate to Customer Management:
   - Verify empty state.
   - Click "Add Customer".
3. Form validation tests:
   - Try submitting empty form (expect validation error: Customer Name or Company Name required).
   - Enter invalid mobile format (expect invalid message).
   - Enter invalid GSTIN / email (expect errors).
   - Dynamic Workers section: Click "Add Worker" multiple times, fill name, designation, save.
4. Transaction test:
   - Submit and verify redirect to `/customers` listing.
   - Verify toast success notice.
5. List Actions:
   - Search by mobile, name, company name.
   - Verify sort by recently added vs. name.
   - Page through customers.
   - Click "View", examine details, add a worker directly, verify.
   - Click "Edit", change customer and worker info, delete a worker, save and verify details update correctly.
   - Click "Delete", verify modal dialog confirmation popups. Reject delete, verify record is intact. Confirm delete, verify cascade delete of customer and workers.
