# Fix SQLite Initialization Error on Clean Database Setup

The application fails to initialize SQLite databases when starting from version 0 (which happens on a clean start, e.g., in browser Incognito mode or a fresh HTTPS hosting deployment). The error thrown is:
`Failed to initialize SQLite database: Run: RunSQL: run: no such table: Attribute`

## Cause Analysis

1. When a clean database is initialized, its version is 0.
2. The `DatabaseService` executes migrations (MigrationV1 through MigrationV5) sequentially.
3. In `MigrationV4`, the old schema tables including `Attribute`, `AttributeValue`, `ProductAttribute`, and `Alias` are dropped, and a new catalog schema with dynamic pricing tables (`Category`, `SubCategory`, `Brand`, `Product`, `ProductVariant`, `PriceList`, `PricingRule`) is created. New seed data matching this schema is executed as part of `MigrationV4`'s statements.
4. Because the database was initialized from version 0 (`isNewDb = true`), `DatabaseService` attempts to execute the `SeedV1` data inserts after migrations finish.
5. `SeedV1` contains DML insert statements targeting the old `Attribute` table.
6. Since the `Attribute` table was dropped in `MigrationV4`, SQLite throws `no such table: Attribute`.
